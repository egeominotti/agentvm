# Multi-CLI implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Launch most coding CLIs in AgentVM and expose native MCP for complete external control, with host-backed credentials and both clients.

**Architecture:** A pure registry describes CLI/provider capabilities. The app resolves launch defaults and Keychain credentials; a fixed-upstream HTTP relay reaches each VM through reverse vsock. Guest scripts construct real argv/configuration and both clients consume the API catalog.

**Tech Stack:** Rust, serde, axum, reqwest/rustls, Swift Virtualization, Python/Bash guest runtime, React/TypeScript/Bun, SwiftUI.

**Spec:** `docs/superpowers/specs/2026-10-14-multi-cli-design.md`

## Global Constraints

- Work directly on `main`; do not create a branch or worktree.
- Never restart or alter the user's engine on port 7777 during development.
- Never write into the shared golden image; clone and test using isolated homes.
- No source file over 300 lines; no mocks/stubs/fakes in tests.
- Write a failing behavior test before implementation.
- Use Bun for dashboard work. Generate API types from Rust.
- Real provider credentials remain in macOS Keychain/host memory, never guest files or environment.
- Preserve existing native changes; coordinate with their owning active task.

## Review Focus

- Old task/settings/snapshot JSON omits every new field and must remain Claude-compatible.
- An agent change must not carry an incompatible model alias or require a Claude token.
- Prompt/model metacharacters must remain literal arguments, including leading dashes and multiline input.
- A server restart must reconnect the host relay of a VM which kept running.
- A custom endpoint/path or upstream redirect must never expose credentials to another origin.

### Task 6: Native MCP and structured VM control (execute before Task 5)

**Spec:** `docs/superpowers/specs/2026-10-14-native-mcp-design.md`

**Files:**
- Create focused native MCP modules under `server/src/mcp/`, `server/src/bin/agentvm-mcp.rs`, `server/src/domain/guest_control.rs`, `server/src/adapters/control.rs`, `server/src/app/control.rs`, `server/src/http/control.rs`, `guest/agent_control.py` and focused exec/files/terminal helpers under `guest/`.
- Modify module declarations/router, Cargo binary/dependency config, and only the control-header branch in `guest/agentvm-pty`. Root handles guest runtime embedding, job startup, existing terminal command selection, helper config and build/app bundling.
- Test: MCP schema/routing/real stdio, real process/file behavior and targeted ignored real-VM execution/files/terminals.

**Interfaces:**
- Use official `rmcp` 3.5.1 (`transport-io`, `schemars`), SDK-owned 2026-07-28 and legacy initialization/discovery compatibility. Stdio stdout contains protocol only.
- Binary consumes `AGENTVM_URL` default `http://127.0.0.1:7777`, validates loopback host, accepts optional command flags for URL. It connects to the existing engine without InstanceLock/AppCtx/recovery/startup side effects.
- Add JSON APIs under `/api/tasks/{id}/control`: `POST /exec` starts argv/cwd/stdin/timeout/limits, `GET /exec/{exec_id}` reads, `DELETE /exec/{exec_id}` cancels; `POST /files` dispatches list/stat/read/write/mkdir/remove/rename; `POST /terminal` dispatches list/capture/input/resize. Existing lifecycle validation remains app-owned.
- Guest connection header is `{\"control\":true}\n`, followed by one big-endian u32 length frame holding `{op,args}`; reply is one length-framed JSON envelope. Limit frames to 16 MiB. Do not put scripts/file contents into the 4096-byte header.
- `guest/agent_control.py: serve(conn)` dispatches handlers, returns structured errors, no global shell state. A capabilities operation identifies supported runtime.
- Guest process execution defaults to cwd `/root/work`, timeout 60 seconds (1..1800), bounded output 1 MiB per stream; argv is literal. Shell execution explicitly uses `/bin/bash -lc`. Start returns `exec_id`; timeout/cancel kills the process group and completes status.
- File reads/writes use base64 bytes, explicit offset/size and default chunk at most 1 MiB; do not mount guest disks or read host arbitrary paths.
- Terminal wire sessions stay `claude`, `shell`, `shell-2`..`shell-9`. Capture/input/resize use actual tmux; literal text does not become shell code in the host or guest control service.
- MCP typed convenience tools plus validated `agentvm_api` cover all JSON REST routes, including credential saves. Archive/file transfer tools accept explicit paths and stream via existing API. JSON API tool rejects non-API paths, absolute URLs, and unsupported methods; results never contain host secret values.
